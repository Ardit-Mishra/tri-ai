# Tri-AI Handoff — 2026-09-21

## Objective

Make Tri-AI a local-first, verification-gated agent operating system for
software, research, and business workflow delivery. A task is accepted only
when its recorded verifier exits successfully; an agent report is never
acceptance evidence.

## Completed in `codex/freellm-router`

- Extended the diagnostic routing policy from one fallback to an ordered chain:
  `OmniRoute :20128/v1 -> FreeLLMAPI :3001/v1 -> Ollama :11434/v1`.
- Preserved the existing safety rule: only `429`, timeout, and connection
  errors advance the probe. Other HTTP errors stop the chain. The probe cannot
  import the board, worker, or executor, and cannot accept work.
- Added `scripts/install-freellmapi.ps1`, which installs the reviewed upstream
  source in `~/.tri-ai/freellmapi`, pins it to
  `b882473c3a23251be312a7270e2e0dc1eae1329d`, binds it to loopback, and never
  writes provider credentials into this repository.
- Added a Claude Code / Codex / Hermes configuration helper. It defaults to
  `--dry-run`; applying client configuration requires the operator's local
  `FREELLMAPI_API_KEY` environment variable.
- Added `docs/FREELLMAPI.md` and `docs/CAPABILITY_CATALOG.md`.

## Remaining operator action

1. Open the local FreeLLMAPI dashboard and add only provider accounts/keys the
   operator owns. Create one unified key.
2. Store that unified key in the user environment as `FREELLMAPI_API_KEY`.
3. Run `scripts/configure-freellmapi-clients.ps1` and inspect its dry-run;
   apply only after confirming the generated client configuration.
4. Fill an out-of-repo routing policy with real model IDs, then deliberately
   preflight each route and retain its evidence before treating FreeLLMAPI as
   an eligible execution fallback.
5. The requested external capability names that do not uniquely identify a
   repository remain intentionally uninstalled. Resolve their owner/URL,
   license, revision, and required permissions first; see
   `docs/CAPABILITY_CATALOG.md`.
