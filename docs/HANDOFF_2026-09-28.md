## 3. What changed today, and how it was verified

### The session boundary (`public-main`)

`b8df28d` sealed private material behind a token. **It did not work in
deployment.** `tailscale serve` proxies the tailnet to
`http://127.0.0.1:3026`, so every remote visitor arrives with
`client_address == 127.0.0.1` and the rule "loopback is the operator"
authorized the whole tailnet. 1,260 tests were green and the live dashboard
was exactly as open as before. This is a fact about topology, not code.

Found by running `tailscale serve status` before restarting, not by testing.
**The same trap applies to Cloudflare Tunnel**, which is the next thing
planned in front of this.

Fixes, in order:

- `f279dc9` — `session_config(env)` returns the token *and* the loopback
  decision together, so "token configured but loopback still trusted" cannot
  be expressed. Adds `GET/POST /login`, `POST /logout`, and a redirect from
  `/` when sealed, because no browser could authenticate before: a phone
  cannot send `X-Kaya-Token` and nothing set the cookie. Cookie is
  `HttpOnly; SameSite=Lax`, plus `Secure` when `X-Forwarded-Proto: https`
  (confirmed: Tailscale Serve sends it).
- `966cf83` — login card overflowed a 375px screen.
- `bb10e08` — `LoginThrottle`. Per-address limits are useless (everyone is
  127.0.0.1 behind the proxy) and delaying a reply throttles nothing on a
  `ThreadingHTTPServer` (parallel guesses overlap their delays), so it
  refuses immediately without examining the key. 4 free attempts, doubling
  waits, capped at 300s. That is what makes a 12-character phone-typeable
  key safe.

**1,292 tests, exit 0.** Mutation-checked: restoring loopback trust fails 1
test; accepting any token fails 2; never tripping the gate, not counting
failures, and checking the key before the gate each fail 3.

Also in this range: `ec20ec6` `brain.capture_run` — the piece Codex announced
in its final session message but did not start.

Verified against the real tailnet URL, not only in tests:

```

/api/snapshot          no session -> sealed:true, 0 items, 0 sources
                       with session -> 796,684 items, 11 sources
```
